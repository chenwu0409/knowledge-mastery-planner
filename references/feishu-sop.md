# 飞书读写 SOP

## 定位与核验

从用户指定的 Base 开始，小兔项目默认使用 [主库绑定](feishu-project.md)。该参考也登记了七张表的现有完整字段结构。用可用的飞书连接器读取表清单和字段清单，按下表匹配名称、类型和关联目标，取得运行时 table ID 和 field ID。跨项目、字段改名、出现同名表或链接类型变化时先核对映射。关键字段无法解析时，仅暂停依赖该字段的写入并报告待写内容。项目绑定文件只提供定位信息，访问使用 Agent 的已有权限。学生原卷、作答照片、访问令牌和记录导出留在授权工作环境。

关联字段写飞书内部 record_id，先按原业务 ID 查询源记录再取得该值。展示与追溯使用业务 ID。读取时按项目时区筛选训练日期，追踪任务的实际关联，再查同一任务的作答和诊断。分页读到范围结束。写入依据以本轮核实的原材料及 live 记录为准。

| 表 | 主键与链接方向 | 工作流使用的实字段 |
|---|---|---|
| 知识点库 | 知识点ID（自动编号，ZSD）。前置知识点、后续关联知识点（链接本表） | 学科、年级、建议掌握等级、当前掌握程度、训练状态（单选）。章节、一级知识点、二级知识点、具体考点、教材版本、考试范围确认依据、范围版本、范围状态、验收标准、覆盖状态、学习状态、当前短板与常见错误、掌握状态变更历史（文本）。最近复测日期（日期）。 |
| 训练任务库 | 任务ID（自动编号，RW）。关联知识点（链接知识点库）、关联题目（链接题目库） | 任务名称、训练目标、目标难度与达成标准、考试阶段与范围依据、优先级与选择理由、实际完成情况、任务复盘（文本）。训练日期、完成期限（日期）。任务状态、训练轮次、学科、难度档（单选）。计划题量、预计用时(分钟)、目标正确率（数字）。 |
| 题目库 | 题目ID（自动编号，TM）。去重键（文本）。关联知识点（链接知识点库）、来源题目（链接本表）、针对错题（双向链接错题诊断库的补救题） | 题目名称、题干、题目来源、来源链接、标准答案、解题解析、评分细则、审核意见与评估明细、风险标记（文本）。题目图片（附件）。难度、题型、审核状态、训练状态、学科、年级（单选）。 |
| 检索与选题记录 | 检索批次ID（文本）。关联训练任务（链接训练任务库）、关联知识点（链接知识点库）、候选题及最终入选题（链接题目库） | 日期（日期）。训练目标、原始提示词、提示词版本、检索平台、筛选条件、候选题链接与待核实资料、每题评估与淘汰原因、检索限制（文本）。结果数量（数字）。 |
| 作答记录库 | 记录ID（自动编号，ZS）。关联训练任务（链接训练任务库）、关联题目（链接题目库） | 日期、复测日期、订正完成日期（日期）。孩子答案、标准答案、步骤得分与判分说明、评分口径、工具使用与自我评价（文本）。答题过程附件（附件）。作答用时(秒)、提示次数、得分、满分（数字）。是否独立完成、错误归因（单选）。订正动作（多选）。正确与否（复选框）。 |
| 错题诊断库 | 错题ID（自动编号）。关联作答记录（链接作答记录库）、关联题目（链接题目库）、关联知识点（链接知识点库）、补救题（双向链接题目库的针对错题） | 错误类型、复测轮次、复测结果（单选）。主要错因、次要错因、错误原因分析、作答证据、纠正方法、推荐变式训练、复测计划与结果历史（文本）。复测日期（日期）。是否掌握（复选框）。 |

跨表引用通过上述原生链接建立。题目与诊断之间的双向链接只写一端并回读两端。作答与任务或题目的关系由作答表出发，查完成情况时反向查询作答表。考试成绩库单独维护正式考试。字段和写入规则见 [七表结构](feishu-project.md)。

## 现有字段如何承载流程

以下是现有表的兼容映射。结构化信息保存在指定文本字段中的独立区块，原字段正文和其他区块保留。用 `[KMP/<区块名>/v1]` 和 `[/KMP]` 围住一段 JSON。每个字段内同名区块至多一个，按完整区块替换，保持历史正文原样。仅写本环节拥有的区块。发现同名区块重复、损坏或记录存在身份冲突时报告，不猜测覆盖。区块是工作流写入约定，不是飞书新增字段。

| 区块与承载字段 | 内容与写入方 |
|---|---|
| target → 知识点库「验收标准」 | 上游写 `scope_key, target_level, acceptance, evidence_refs, confidence, missing`。一个区块内以考试或范围版本标识分别保存仍需保留的目标。范围或目标改变的事实另记「考试范围确认依据」。 |
| mastery → 知识点库「掌握状态变更历史」 | 上游写已验证 L 或未知、稳定性、当前依据、置信度和变更历史。每条变更引用作答 ID 及事件键。只有实际完成复测时才写「最近复测日期」。 |
| plan → 训练任务库「训练目标」 | 上游写 `task_key, plan_version, horizon, purpose, window, trigger, scope_key, scope_status, zsd_ids, search_not_before, search_request, budget_minutes, state, evidence_rule_version, confidence, evidence_gaps`。计划状态用 `tentative / ready / deferred / cancelled`。具体日期已确定才写「训练日期」，窗口保存在区块。 |
| selection_result → 检索与选题记录「每题评估与淘汰原因」 | 下游保存候选批次的 RW、计划版本、候选题及缺口。已发布候选交上游验收。 |
| pack_result → 同批次「每题评估与淘汰原因」 | 下游凭放行清单记录成品状态、验收版本、已用题目小问和题包引用。发布顺序见 [异步搜题交接](async-selection.md)。 |
| delivery → 训练任务库「任务复盘」 | 上游按计划版本和批次保存审核版本、审核结论、缺口、`approved_items`、成品检查和实际发放证据。验收状态用 `needs_research / scope_hold / approved_for_pack`。补搜只读当前 delivery，题目审核意见仅可存任务与批次指针及题目本身的缺陷。每项任务由上游维护唯一的 active_review，历史放行保留以便判读旧作答。成品检查和发出另记。历史作答沿用当次发放版本。 |
| progress → 训练任务库「实际完成情况」 | 上游写 `answer_state, attempt_refs, scored_subitems, next_task_refs`。状态用 `awaiting_evidence / partial / completed`。按本次任务要求的可评分小问判断执行是否完成。保留已提交、未提交、明确跳过及未知的区别，已提交可带提示。独立达标由 mastery 另行判断。 |
| attempt → 作答记录库「步骤得分与判分说明」 | 上游写 `attempt_key, event_keys, attempt_kind, plan_version, subitems, evidence_refs, grading_state`。每个小问记录考点、评分、关键步骤、独立性及提示或看答案的证据，区分首次、订正和复测。作答表顶层独立性按整题汇总，单问更正只改变该小问和受影响的汇总。 |
| diagnosis → 错题诊断库「作答证据」 | 上游写 `diagnosis_key, attempt_key, subitem, zsd_id, evidence_refs`，订正及复测变更追加到「复测计划与结果历史」。 |

知识点库「建议掌握等级」实有 `L1基础 / L2熟练 / L3综合`，期中 L1–L4 由 target 区块保存。「当前掌握程度」仅有 `未掌握 / 部分掌握 / 已掌握`，沿用项目确认的历史口径，已验证层级与稳定性由 mastery 保存。训练任务「任务状态」实有 `未开始 / 进行中 / 已完成 / 已取消`，按真实执行进度填写。题包生成记录在 pack_result，放行及发出证据记录在 delivery。题库「审核状态」实有 `待审核 / 已通过 / 已淘汰`，任务适配的三档审核由 delivery 保存。未知评分以 `grading_state` 明示，空白或默认 false 的复选框无法证明错误或未掌握。

## 事件 → 写入

| 事件 | 读入与写入顺序 |
|---|---|
| 收到学校试卷、范围、教学进度或更正 | 先读匹配范围的 ZSD、原章节和当前依据。按卷名、日期、题号和小问写「考试范围确认依据」，仅对有新证据的条目更新「范围状态」「范围版本」和 target。核对当前及未来 RW，有依赖的才改计划版本。孩子解答另走作答流程。资料引用使用已获授权的飞书地址或可接续的来源标识。 |
| 证据支持新增知识点 | 按学科、章节、一级、二级和具体考点核对同义条目。匹配既有条目则补证据并复用 ZSD。确属新点时写学科、年级、章节、一级知识点、二级知识点、具体考点、范围版本、范围状态、考试范围确认依据及可核实的前后置关系。由飞书生成 ZSD，回读后写目标和计划。 |
| 形成日、周、月计划或调整任务 | 先查原 task_key 和同知识点开放复测任务。创建或更新 RW 的「任务名称」「学科」「关联知识点」「训练日期」「完成期限」「计划题量」「预计用时(分钟)」「目标难度与达成标准」「考试阶段与范围依据」「优先级与选择理由」及 plan。预算或日期未知时保留待确认。一个可执行时段内的周、月占位转换为当日任务时，能沿用同一 RW 则更新原行。阶段计划若拆分为多个执行任务，在 plan 中记录父计划 RW 并分别使用稳定键。 |
| 到期并触发搜题 | 下游按 [异步搜题交接](async-selection.md) 领取并执行。写或复用 TM、记录候选批次和候选题关联，回读后发布候选并交上游验收。 |
| 验收候选或退回补搜 | 上游逐题与计划对照，将放行小问或补搜条件写 delivery。未放行时下游按退回要求补搜并交验。 |
| 制卷、发放或发现题包问题 | 下游按放行清单写最终入选题、任务关联题目及 pack_result。上游有实际发放证据才记录发出。只在题面或答案本身有通用质量问题时更新题库「风险标记」「审核意见与评估明细」。避免以单次适配结论覆盖通用审核状态。题包问题只调整发放、复核及修订，不生成孩子的错题诊断。 |
| 收到孩子首次作答或复测 | 校验日期及 RW→TM，并按 attempt_key 写或补充 ZS 的两个关联、日期、孩子答案、附件、独立性、提示次数、用时、评分口径和 attempt。已有可用分值才写「得分」「满分」，答案或评分未知时保留未知。诊断按 ZS、小问、ZSD 定位，写关联、作答证据、错因与纠正方法。再更新知识点 mastery 和任务 progress。复测实际发生时写复测结果、日期、轮次及历史。 |
| 家长修正作答信息 | 有明确原 attempt 时补充原记录，保留旧判断与更正原因。若小问看过答案，撤回该小问的独立达标推断，保留其提交事实、可核对的评分以及其他小问的独立证据。新一次作答使用新 attempt。重算受影响的诊断、mastery、progress 和开放复测任务。若因此失去达标证据，按剩余证据更新验证状态。 |

## 重试、并发与回读

- 对同一项目、同一事件或计划键串行写。若工具支持条件更新，比较读到的修订标识后再写。没有条件更新时，协调单一写入者，写前重读受影响字段，检测到更改则重新合并或报告冲突。题目关联新增用集合并集，保留其他已挂题。移除或改用明确证据限定到受影响的关联。
- 旧记录首次使用时先按原业务 ID 定位。没有 ID 时用关联、日期或窗口、用途及轮次查找，能唯一对应时在原行补写定位键，存在多个合理候选时先核对。新记录创建时同批写业务定位键和必需关联。计划键使用项目内稳定的周期或窗口标识、学科、用途和排序槽。调整日期和题量保留原键。复测先用 ZSD、用途及开放状态匹配已有任务，避免同点重复排队。选择批次键使用任务键、计划版本及批次槽。TM 以题源平台与原题号去重。旧去重键的格式不同，先核对「来源链接」和题号。作答键使用 RW、TM、作答事件或明确轮次，同一份补拍附件追加到同次作答，重复提交可用来源消息或附件内容指纹确认。诊断键使用 ZS、题目小问及 ZSD。
- 可安全重试前先按键回读。创建超时后先查结果。匹配不唯一时停止依赖的写入。附件重传前检查已有关联和内容标识。失败后从已确认的记录或批次继续。依赖顺序为源记录、链接、派生结论、任务状态。若中途失败，记录已确认的 ID、未完成的写入和恢复入口。
- 完成后回读本轮改动字段及关联，核对目标版本、批次、作答证据和下一任务。状态以回读结果报告。原字段无法安全映射时，以含目标表、字段、类型、值和关联的待写清单收尾。
